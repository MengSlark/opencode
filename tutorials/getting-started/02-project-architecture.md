## 2. 核心概念

### 2.1 会话（Session）

**定义**：一次完整的 AI 对话过程

**生命周期**:

```
创建 ──► 活跃 ──► 暂停 ──► 恢复 ──► 结束
 │        │        │        │        │
 │        ▼        │        │        ▼
 │    接收消息     │        │   持久化存储
 │    调用工具     │        │
 │    等待输入     │        │
```

**关键组件**:

- **Messages**: 消息历史（user/assistant/tool）
- **Context**: 对话上下文
- **State**: 当前状态（等待中/处理中/错误）

### 2.2 工具（Tool）

**定义**：Agent 可调用的功能单元

**结构**:

```typescript
Tool.define(name, {
  description: "AI 理解工具的说明",
  parameters: z.object({...}),  // 输入参数
  execute: async (params, ctx) => {
    // 执行逻辑
    return { output, metadata }
  }
})
```

**内置工具**:
| 工具名 | 功能 | 使用场景 |
|--------|------|----------|
| grep | 代码搜索 | 查找代码 |
| read | 文件读取 | 查看文件内容 |
| edit | 文件编辑 | 修改代码 |
| bash | 命令执行 | 运行命令 |
| question | 用户询问 | 需要确认时 |
| skill | 技能调用 | 执行预定义操作 |

### 2.3 提供商（Provider）

**定义**：AI 服务的抽象接口

**支持的提供商**:

```
┌────────────────────────────────────────────┐
│              Provider 接口                  │
│  ┌──────────────────────────────────────┐  │
│  │  chat.completions.create()           │  │
│  │  - stream: boolean                   │  │
│  │  - messages: Message[]               │  │
│  │  - tools: Tool[]                     │  │
│  └──────────────────────────────────────┘  │
└───────────────────┬────────────────────────┘
                    │
    ┌───────────────┼───────────────┐
    ▼               ▼               ▼
┌─────────┐   ┌─────────┐   ┌─────────┐
│ OpenAI  │   │Anthropic│   │ Google  │
│ GPT-4   │   │ Claude  │   │ Gemini  │
└─────────┘   └─────────┘   └─────────┘
```

### 2.4 Agent

**定义**：核心决策引擎，协调会话、工具和 AI

**工作流程**:

```
1. 接收用户输入
       │
       ▼
2. 构建上下文（历史消息 + 系统提示）
       │
       ▼
3. 调用 AI Provider
       │
       ▼
4. 解析 AI 响应
   ├─► 如果是文本 → 直接返回用户
   ├─► 如果是工具调用 → 执行工具
   └─► 如果是需要确认 → 询问用户
       │
       ▼
5. 循环直到完成
```

## 3. 数据流

### 3.1 单次请求流程

```
用户输入
    │
    ▼
┌─────────────────────────────────────┐
│ 1. Session 接收消息                  │
│    - 保存用户消息                    │
│    - 触发 Agent                     │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│ 2. Agent 构建 Prompt                │
│    - 系统提示词                     │
│    - 历史消息                       │
│    - 可用工具列表                   │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│ 3. Provider 调用 AI                 │
│    - 发送请求                       │
│    - 接收流式响应                  │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│ 4. 解析 AI 响应                     │
│    ├─ 文本内容 → 返回用户           │
│    ├─ 工具调用 → 执行工具           │
│    └─ 需要权限 → 询问用户           │
└──────────────────┬──────────────────┘
                   │
                   ▼
┌─────────────────────────────────────┐
│ 5. 工具执行（如果需要）              │
│    - 验证参数                       │
│    - 执行操作                       │
│    - 返回结果                       │
└──────────────────┬──────────────────┘
                   │
                   ▼
         返回步骤 2（循环）
                   │
                   ▼
              完成，返回结果
```

### 3.2 状态管理

```typescript
// 会话状态
interface Session {
  id: string // 唯一标识
  projectId: string // 所属项目
  messages: Message[] // 消息列表
  metadata: {
    model: string // 使用的模型
    createdAt: Date
    updatedAt: Date
  }
}

// 消息类型
type Message =
  | { role: "user"; content: string }
  | { role: "assistant"; content: string; tool_calls?: ToolCall[] }
  | { role: "tool"; tool_call_id: string; content: string }
```

## 5. 关键技术决策

### 5.1 为什么选择 Bun？

| 特性       | Node.js       | Bun      | 优势       |
| ---------- | ------------- | -------- | ---------- |
| 启动速度   | 中等          | 快       | 开发体验好 |
| TypeScript | 需配置        | 原生支持 | 零配置     |
| API 设计   | 传统          | 现代化   | 更简洁     |
| 包管理     | npm/yarn/pnpm | 内置     | 统一工具   |

### 5.2 为什么使用 SolidJS？

- **性能**：无虚拟 DOM，编译时优化
- **响应式**：细粒度更新，自动追踪依赖
- **轻量**：体积小，学习曲线平缓
- **类型安全**：与 TypeScript 完美结合

### 5.3 Monorepo 的优势

```
传统多仓库                Monorepo
┌──────────┐            ┌──────────────────┐
│  repo-A  │            │  packages/       │
│  repo-B  │  ─────►    │    ├── opencode/ │
│  repo-C  │            │    ├── app/      │
└──────────┘            │    ├── sdk/      │
   版本不一致            │    └── util/     │
   依赖重复              └──────────────────┘
                           统一版本
                           共享代码
```

## 7. 扩展点

系统设计了多个扩展点，方便二次开发：

### 7.1 自定义工具

```typescript
// packages/opencode/src/tool/my-tool.ts
export const MyTool = Tool.define("my_tool", {
  parameters: z.object({...}),
  async execute(params, ctx) {
    // 你的逻辑
  }
})
```

### 7.2 自定义提供商

```typescript
// packages/opencode/src/provider/my-provider.ts
export class MyProvider implements Provider {
  async chat(options) {
    // 调用你的 AI 服务
  }
}
```

### 7.3 自定义插件

```typescript
// 插件 manifest
{
  "name": "my-plugin",
  "tools": ["tool1", "tool2"],
  "entry": "./index.ts"
}
```

## 8. 总结

### 关键要点

1. **分层架构**：用户层 → API 层 → 服务层 → 核心层 → 基础设施
2. **核心组件**：Session + Agent + Tool + Provider
3. **数据流**：用户输入 → Agent 决策 → 工具执行 → 结果返回
4. **扩展性**：工具、提供商、插件都可自定义
